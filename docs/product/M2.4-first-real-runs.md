Public surfaces only: the built portfolio home page, the pm-tools repo clone, and the portfolio claims register (read, nothing copied). No finding below has been shown to Chase yet, so none is accepted.

## intake (SKT-27)
- On the real home page it refused at first, then passed with `--allow-email` for the address the page publishes on purpose, after a workaround (block-level closing tags followed by a space in a scratch copy; the page itself was not changed). 216 quotes, 4 uses of the allowed address.
- **R40 (P1):** the tag-stripped scan variant glues text across block tags (`roles.` + the address), so the allowed address no longer matches and the run refuses. It fails closed, but the real page cannot be read without the workaround. Fix: treat block tags as a space in that variant, keep inline tags glued (the R30 cases).
- **R41 (P2):** `&darr;` and `&rarr;` are left undecoded in the quotes.
- **R42 (P1 for READMEs):** one quote per sentence splits wrapped lines and table rows, and reviewers read the splits as README bugs (see `evals/stakeholder/runs/2026-11-24-first`).
- A repo run refuses over 200 files or 50 MB; not hit here because the READMEs were read as single files.

## repo-check (SKT-1..8) on the pm-tools clone
- Needed `--allow-unscanned` because the repo holds font files; 3 listed as unscanned.
- 6 findings: no CONTRIBUTING, no code of conduct, no issue or PR templates, root clutter (planning files in the root), no CI badge: all true when checked by hand. The pinning finding is true for 3 of 5 action uses, but its fix text says to commit a lockfile that already exists. **R43 (P2):** fix text should not mention a lockfile when one is present.
- 6 items under needs_github_data, 5 under needs_human: not judged, as designed.

## claim-check (SKT-17) on the home page against the real register
- The register has more than one table; the tool read the `Claim`/`Status` one and skipped 8 rows (status values not recognized). The README's earlier note that it would refuse the whole file was wrong; corrected here.
- It refused its own intake's output until `--allow-email` was passed. **R44 (P2):** not worth fixing; document it.
- 30 findings, first 10 shown. By my reading, about half of the first 10 would be rejected: "agent" matched in sentences about a past employer's agents (4), and "See what I built" matched as a built claim (1). Real ones: "Three products are built and four in progress", "48 hours", the 80% and 14% case-study numbers, "1 hour". **SKT-17 asks for at most 3 of 10 rejected, so it is not met**; Chase decides which are noise.
- **R45 (P1):** claim-check needs a way to scope the watch words to product claims, or an ignore list for case-study text, before it is useful on this page.
