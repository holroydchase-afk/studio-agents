## Decisions to review
- story-keeper triggers through its "use proactively" description and the project-instructions rule, not a Stop hook: a hook would cost tokens on every turn, and repo hooks don't load in cloud project threads anyway. It's a separate agent from positioning so logging stays cheap and runs every time, while positioning turns the log into copy.
- QA-R4: a project-only skill with the same name as a studio skill is overwritten on sync, and a skill an agent stops preloading stays in product repos. Same rule as agents (studio names win, sync never deletes).
- `sync.sh` installs only the skills a synced agent preloads, not every plugin skill: the others (digest, night-prep, onboard...) are Chase's account-level skills for chats, and copying them into every product repo would add noise and drift.
- Supabase starter: membership helpers (works for users in several orgs, like Hearth) rather than Crew Clock's token-claims hook; the README says when to add the hook. Copied with a script, not published as a package.

- Security kit runs gitleaks as a pinned, checksum-verified binary instead of `gitleaks-action`, so there's no third-party action and no license key. CodeQL is a workflow file (advanced setup) so no Settings click is needed; a repo that already uses default setup should drop the file.
- V checks warn by default and fail CI only with `--strict-visual`: the portfolio, a reference product, fails V2 today, and a visual limit is a judgment a product may override with a Layer 3 exception. The spacing scale (V3) isn't code-checked: Build Slate and the portfolio both use 10/14/18px spacing, so a 4px-grid check would flag the references.
- One ux-reviewer, not separate UI and UX agents: the misses came from judging pixels by eye, so the split is by method inside one agent (code checks, then rules, then opinion). Revisit if a product grows its own component library.
- Layer 1 rules sit inside `ux-reviewer.md` rather than in the doc, so they're loaded wherever the agent runs (evals, a repo that hasn't synced). `tests/check.sh` fails if ux-rules.mjs checks a rule the agent doesn't define.
- architect is synced to product repos (unlike orchestrator and focus-coach) so each project can review its own stack changes; the cross-repo drift sweep only runs from Product Studio and sends INTAKE blocks, never edits.
- The shared checks live in `templates/scripts/`, not `scripts/`, because `scripts/` holds studio-agents' own tools and these get copied into product repos (same as `templates/handoff-check.yml`). The config file is `studio-checks.json` with one section per check; the coming shared privacy check is meant to add a `private` section there instead of a second file.
- ux-shots' 0-10 polish score (#14) was folded into the visual score #20 added (anchors 2/5/8/10, 8 is the bar), so there's one scale, defined in `ux-reviewer.md`.
- ux-shots reports measurements, not verdicts: inline links in a sentence are exempt from WCAG 2.5.8 but still listed, so ux-reviewer judges them from the screenshot. Product-specific overlays (Role Radar's preview panel, recruiter details) stay in each product; `--click` covers tabs and buttons.
- night-prep hands tonight's goal to the run through project memory (`tonight.md` plus an index line) instead of rewriting the scheduled run's prompt, because the run's GOAL line already says Chase's steer wins and memory loads into every session.
- Planning codes for the new projects: CHL (Charlie) and CRW (Crew Clock). Rename in place if Chase prefers others.
- "Use proactively" wording in descriptions makes Claude Code delegate without being asked; if it over-triggers (for example ux-reviewer on internal-only changes), trim the description, not the table.
- focus-coach reads a tracker at a default project-files path; any project can point it elsewhere via CLAUDE.md or memory.
- MIT, like the other public studio repos, so others can reuse the agents.
