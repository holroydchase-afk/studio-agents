# Plan: larger portrait on the portfolio home page

**Bottom line:** this is blocked on one input I don't have. The repo's only portrait is a small file, and the design shows it at 1600px wide on large screens. Stretching the small file to 1600px will look soft and pixelated. So the first step is getting a higher-resolution original photo from Chase. Everything else in the plan is small and can be built the moment that photo exists.

## Blocker (one step for Chase)
Send or drop the original portrait file (the full-size photo, not a screenshot or a previously compressed copy) into the repo or the thread. Ask for the largest version he has. Target at least 3200px wide, which covers a 1600px slot on 2x (retina) screens. 1600px wide is the bare minimum and only sharp on 1x screens.

If the original can't be found, the fallbacks, in order:
1. Re-shoot or export from the phone's camera roll (phones usually produce 3000px or wider).
2. Cap the portrait's display size at the small file's real width, and change the design to match. This needs Chase's call, since it changes the design.
3. Do not upscale the small file and ship it as if it were sharp. An AI upscale also changes how Chase's face looks, which is a real concern for a portfolio portrait. Only do it if Chase explicitly asks.

## Plan once the photo arrives
1. **Put the original aside, not on the page.** Keep the full-size source out of the deployed folder (or in a clearly named `source/` folder if the site is public and size is fine). Check it for embedded location or camera data and strip it before anything is published.
2. **Generate responsive sizes.** Produce a few widths (for example 800, 1200, 1600, 2400, 3200px) in WebP, with a JPEG fallback. Keep each file reasonably small; the 1600px version should be well under about 300 KB.
3. **Wire up the page.** Use `srcset` and `sizes` so small screens load the small file and large screens load the 1600px or 2x version. Set explicit `width` and `height` so the page doesn't jump while loading, and add real `alt` text. Don't lazy-load it if it sits at the top of the page, since it is the main image people see.
4. **Page source.** Page content in this repo is generated by `tools/build.py`, so the change goes there and the HTML is regenerated, not hand-edited.
5. **Check it.** Look at it at phone, laptop and 1600px+ widths, on a normal and a retina screen if possible. Confirm it's sharp at 1600px, the face isn't cropped on narrow screens, and page load time hasn't gotten noticeably worse.

## Process and release notes
- The site is public and a push to `main` deploys it live, so this goes in a PR and waits for Chase's go before merging.
- Update `HANDOFF.md` in the same PR (done, next step, blockers).
- The PR needs an `Agents:` line. This is a user-facing visual change, so the UX reviewer should look at it, and the privacy check should confirm no photo metadata is published.
- Don't commit a photo that contains anything other than what Chase already publishes on the site.
