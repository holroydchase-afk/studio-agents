In the meantime, here's the rule I'd use. Name the repo after the product, in lowercase with hyphens: `crew-clock`, `energy-scanner`, `role-radar`. That matches your other repos. It also reads well on your portfolio and in a recruiter's GitHub tab.

Avoid `-app`, `-v1`, `-demo` and `-project` suffixes. They add nothing, and renaming later breaks links.

If the product name isn't final, hold off on creating the repo, because a rename later is a chore. Which project is it?
